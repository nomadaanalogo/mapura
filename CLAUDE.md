# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Next.js 15 (App Router, TypeScript) marketing site for Mapura Grupo Consultor, a legal services firm in Palmira, Valle del Cauca, Colombia. Content is entirely Spanish-language, heavily SEO-oriented (per-page `Metadata`, JSON-LD structured data), and organized as stacked landing-page sections rather than deep navigation.

## Commands

Package manager is pnpm (see `pnpm-lock.yaml`).

```bash
pnpm dev      # local dev server
pnpm build    # production build check
pnpm lint     # next lint
```

There is no test suite; validate changes via `pnpm build` and `pnpm lint`, and by checking the page in a browser for visual/layout changes. Note `next.config.mjs` sets `eslint.ignoreDuringBuilds` and `typescript.ignoreBuildErrors` to `true`, so `pnpm build` will succeed even with type or lint errors — run `pnpm lint` and check `tsc` separately if you need real signal on those.

## Architecture

- **Two landing pages, same pattern**: `app/page.tsx` (main site) and `app/insolvenciaeconomica/page.tsx` (insolvency-law campaign landing page) each export their own `Metadata` (title/description/keywords/OG/Twitter) and inline JSON-LD `<script>` blocks, then compose a sequence of section components from `components/`. There's also `app/politica-privacidad/page.tsx` for the privacy policy. When adding a new page, follow this same metadata + JSON-LD + section-composition shape.
- **Sections are self-contained**: each `components/*-section.tsx` (e.g. `hero-section`, `services-section`, `contact-section`, `contact-section-insolvency`) is a standalone block used by one or both pages — there's no shared layout/grid system between them beyond global Tailwind styles.
- **Lead capture goes to Google Apps Script, not an API route**: `contact-section.tsx` and `contact-section-insolvency.tsx` `POST` form data directly (as `x-www-form-urlencoded`) to a deployed Google Apps Script web app URL (hardcoded `script.google.com/macros/s/.../exec`). `google-apps-script.js` at the repo root is the source for that deployed script (writes to a Google Sheet, sends confirmation + notification emails) — it is **not** built or deployed by this Next.js app; it must be copied into the Apps Script editor manually when changed. After submitting, both forms redirect the user to a pre-filled WhatsApp link (`wa.me/...`). If either the form fields or the expected payload shape change, update both the React form and `google-apps-script.js` in tandem.
- **UI primitives**: `components/ui/*` is a shadcn/ui (`components.json`, style "new-york", base color "neutral") component set — treat these as generated/library-like primitives and prefer composing them from section components rather than editing extensively.
- **Styling**: Tailwind CSS v4 via `app/globals.css` (also mirrored at `styles/globals.css`); no `tailwind.config` file (config is CSS-based per `components.json`'s empty `tailwind.config`). Brand colors recur as hex literals in section components (e.g. `#2C3E50`, `#4EA5A7`) rather than semantic tokens — match existing hex usage when styling new sections.
- **Import alias**: `@/*` per `tsconfig.json` (`@/components`, `@/lib`, `@/hooks`, `@/components/ui`).
- **Images**: static assets in `public/images/`; use `next/image` for local images. `next.config.mjs` whitelists one remote image host (`hebbkx1anhila5yf.public.blob.vercel-storage.com`).
- Generated by v0.app (per `app/page.tsx`'s `generator` metadata field) — expect some v0-style conventions (inline JSON-LD, hex color literals, single-file sections) throughout.

## Working rules

- Prefer small, focused edits in existing components instead of large rewrites.
- Preserve Spanish copy and SEO metadata (title/description/keywords/JSON-LD) when editing marketing pages; keep contact details, legal service names, and geographic references (Palmira, Valle del Cauca, Cali, etc.) consistent across sections.
- Do not introduce unrelated frameworks or state-management libraries unless the task clearly requires them.
- If a design or metadata change affects layout or SEO, verify in the browser and keep the aesthetic aligned with the existing legal-brand look.
